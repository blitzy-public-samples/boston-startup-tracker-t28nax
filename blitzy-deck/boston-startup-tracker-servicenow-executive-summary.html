Boston Startup Tracker, rebuilt on ServiceNow

A venture-data product that could not be built or started is now one specified application: a validated package, plus the guides that build the rest.

How data arrives and leaves

flowchart LR
  accTitle: How data reaches the tables and how it leaves them
  accDescr: Crunchbase and LinkedIn each reach a named connection bound by name, and the two connections feed two scheduled flows running on a cadence between six and forty-eight hours. Crunchbase is the only source with a published read contract, and it is not live until its key is supplied. LinkedIn publishes no read interface for people or third-party job postings, so its call confirms company identity only and its rows come from the fallback dataset of six files and sixty-five rows, which also stands in for Crunchbase while that key is outstanding. Four cleaning rules run before anything is written to ten tables. Access control with forty-nine rules then guards both ways out: an interface layer of thirty-one operations and a Service Portal of five pages.

How it will be proven

  • 9 Pre-ship checks
  • 36 Tests, in ten suites
  • 100% Tables and resources covered
  • 11 Gates checked after install 
flowchart LR
  accTitle: The checks between a package and an accepted installation
  accDescr: Nine package checks run first, then the package is imported and previewed within a six-hundred-second budget. If the preview reports any problem the package is fixed and re-issued; if it reports none the package is committed. Fifteen checks then decide acceptance and all fifteen must pass. Of those fifteen, only the eleven required gates trigger a roll back; a failure of one of the other four, being the column count and the three security checks, is corrected in the package and re-issued instead.

timeline
  accTitle: The migration timeline, in three phases
  accDescr: Three phases in relative order. Install: validate the package, then import, preview and commit it, then clear the fifteen acceptance-blocking checks.
